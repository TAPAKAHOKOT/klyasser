# Кляссер на Cloudflare Workers

Тот же сервер, что `../server.js`, только в Cloudflare: аккаунты, PIN и состояние ленты — в D1,
фото — в R2 или прямо в D1, а `../public/index.html` раздаётся как статика. Фронтенд не меняется.

## Что бесплатно, а что нет

| сервис | бесплатно | карта |
|---|---|---|
| Workers | 100 000 запросов в сутки, 10 мс CPU на запрос | не нужна |
| D1 | 500 МБ на базу, 5 ГБ всего; 5 млн прочитанных и 100 тыс. записанных строк в сутки | не нужна |
| R2 | 10 ГБ·месяц, 1 млн операций класса A и 10 млн класса B в месяц, исходящий трафик бесплатный | **нужна**, перерасход ничем не ограничен — придёт счёт |

Где хранить фото — переменная `STORAGE` в `wrangler.jsonc`:

- `"r2"` (по умолчанию) — фото до 25 МБ, места с запасом. Нужна карта в аккаунте Cloudflare.
- `"d1"` — без карты. Каждое фото не больше 1,9 МБ, всё вместе — не больше 500 МБ
  (примерно 1000+ фото: оригинал ~300–400 КБ + превью ~50 КБ).
  Минус: D1 передаёт файлы медленно, и на бесплатном тарифе открытие или загрузка оригиналов
  от ~0,5 МБ может не уложиться в 10 мс CPU (ошибка 1102). С превью проблем нет.

## Деплой (по шагам)

Все команды — из папки `cloudflare`.

1. Заведи аккаунт: https://dash.cloudflare.com/sign-up (бесплатно).
2. Поставь зависимости и войди:
   ```bash
   npm install
   npx wrangler login
   ```
3. Создай базу:
   ```bash
   npx wrangler d1 create klyasser
   ```
   Скопируй `database_id` из ответа в `wrangler.jsonc` (там сейчас id базы автора — у тебя он будет свой).
   Там же блок `routes` с доменом автора: поставь свой поддомен (зона должна быть в этом же аккаунте Cloudflare)
   или удали блок — тогда сайт будет только на `workers.dev`.
4. Выбери, где хранить фото:
   - **R2:** в панели Cloudflare открой R2, привяжи карту, потом
     ```bash
     npx wrangler r2 bucket create klyasser-photos
     ```
   - **D1 (без карты):** в `wrangler.jsonc` поставь `"STORAGE": "d1"` и удали весь блок `r2_buckets`.
5. Создай таблицы:
   ```bash
   npm run db:migrate:remote
   ```
6. Задай секрет для подписи входа. Сгенерируй его и вставь, когда wrangler спросит
   (если спросит, создавать ли Worker, — отвечай «да»):
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   npx wrangler secret put KLYASSER_SECRET
   ```
   Не меняй секрет потом: иначе все выйдут и им придётся снова вводить PIN.
7. По желанию — код приглашения, без которого нельзя создать аккаунт:
   ```bash
   npx wrangler secret put KLYASSER_INVITE
   ```
8. Выложи:
   ```bash
   npm run deploy
   ```
   Адрес будет вида `https://klyasser.<твой-поддомен>.workers.dev`.

Обновить код потом можно той же командой: `npm run deploy`.
Сделать бэкап базы: `npx wrangler d1 export klyasser --remote --output backup.sql`.
Фото из R2 в этот файл не попадают.

## Локально

```bash
cp .dev.vars.example .dev.vars    # и впиши любой длинный KLYASSER_SECRET
npm run db:migrate:local
npm run dev                       # фото в локальном R2;  npm run dev:d1 — фото в D1
```

Открой http://localhost:8787. Всё хранится в `.wrangler/` и не связано с Cloudflare: вход не нужен.

## Чем отличается от server.js

- PIN хешируется через PBKDF2-SHA256 (10 000 итераций): scrypt не влезает в 10 мс CPU.
  От перебора защищает блокировка. Базу и фото из `../data` автоматически сюда не перенести.
- Счётчик неверных PIN хранится в D1 и переживает перезапуски. Попытка засчитывается до проверки PIN,
  поэтому параллельные запросы не обходят лимит в 5 попыток.
- Состояние ленты больше 1,9 МБ не сохранится (ответ 413): это лимит строки в D1.
- Без `KLYASSER_SECRET` API отвечает 500: в отличие от server.js, Worker не может сам сохранить секрет.
- Если в `../public` появятся другие файлы, они тоже будут раздаваться (server.js отдавал только index.html).
